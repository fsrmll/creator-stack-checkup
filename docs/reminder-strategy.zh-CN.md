# 提醒策略

第一版提醒坚持无后端、低风险、用户自己掌控。

## 为什么不做浏览器 SMTP 发信

普通网页不适合让用户填写 SMTP 密码并自动发邮件，原因有三个：

- 浏览器前端无法稳定、安全地直接连接常规 SMTP 服务。
- SMTP 密码如果放进前端或 localStorage，泄露风险很高。
- 一旦做自动发信，产品就需要处理风控、滥用、退信、限额和服务商封禁。

所以第一版不收集 SMTP 密码，也不提供自动邮件提醒。

## 第一版支持的提醒方式

- `.ics` 文件：下载后导入系统日历。
- Google Calendar 链接：打开用户自己的 Google 日历并预填事件。
- Outlook Calendar 链接：打开用户自己的 Outlook 日历并预填事件。
- `mailto:` 链接：打开用户默认邮箱客户端，用户自己点击发送。
- `sms:` 链接：在手机上打开短信 App，用户自己发送给自己。
- 浏览器 Notification：只在用户允许且当前浏览器支持时显示本地通知，不承诺后台精准定时。

## 用户应该怎么用

最可靠的方式是日历提醒：

1. 在工具里填写下次续费日期。
2. 到提醒中心。
3. 对快续费的工具点击日历按钮。
4. 在 Google Calendar、Outlook 或系统日历里确认事件。

邮件和短信链接更适合临时提醒，不适合作为长期自动提醒系统。

## 未来可以加什么

如果以后要做 Pro 版，可以考虑：

- 用户自愿登录后的云同步。
- 服务器端邮件提醒。
- 可选短信提醒。
- 日历订阅 feed。
- 自部署后端模式。

这些都不进入第一版，因为它们会引入账号、隐私、费用和运维复杂度。
